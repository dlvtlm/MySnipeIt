### A3-EXT — השוואה למחשבון בליסטי חיצוני

**מה נמדד:** שלב 2 של פרק 10, שבו הפתרון מושווה לחישוב מקובל בסטייה של עד חמש מעלות.

**נדרש:** דפדפן בלבד. לא נדרש קוד.

**הרצה:**

1. פתח את מחשבון JBM Ballistics בכתובת `jbmballistics.com/ballistics/calculators/calculators.shtml`
   ובחר `Trajectory - Simplified`.
2. הזן את הפרמטרים של 7.62×51 M80 כפי שהם מוגדרים ב-`BallisticProfiles.kt`:
   מקדם בליסטי G1 של 0.395, משקל קליע 147 גרעין (9.53 גרם), מהירות לוע 838 מטר לשנייה,
   גובה כוונת 38 מילימטר, אפס ב-100 מטר.
3. הרץ עבור חמישה טווחים: 50, 100, 300, 600 ו-1000 מטר, באטמוספירת ICAO תקנית וללא רוח.
4. תעד את הנפילה ואת זמן המעוף שהמחשבון מחזיר.
5. הרץ את A3 והשווה מול שורות המרחק המתאימות.
6. המר את נפילת הקליע מיחידות אורך למעלות באמצעות `atan(נפילה במטרים / טווח במטרים)`
   כדי להשוות ליחידות של המערכת שלנו.

**מה לתעד:** טבלה של חמש שורות ובה טווח, נפילה לפי המחשבון, נפילה לפי המערכת, סטייה במעלות,
זמן מעוף לפי המחשבון, זמן מעוף לפי המערכת.

**צפוי:** סטייה של עד חמש מעלות. הפרשים בזמן המעוף צפויים להיות קטנים יותר, משום שזמן מעוף
רגיש פחות לפרטי מודל הגרר מאשר הנפילה.

**מה לכתוב בפרק:** יש לציין במפורש באיזה מחשבון השתמשתם ובאילו פרמטרים. מחשבון מקוון מקובל

### A6 — אימות חוזר של הסקירה האקוסטית עם FFTW אמיתית

**מה נמדד:** שהמספרים מ-A4 משתחזרים עם ספריית ה-FFT האמיתית ולא עם המימוש החלופי.

**למה זה נדרש:** מסמך התשובות מציין במפורש שההרצה נעשתה בסביבה ללא `libfftw3f`, עם מימוש
חלופי שאומת מול NumPy לדיוק של 3.7 כפול 10 בחזקת מינוס 8. זה תקף מבחינה מתמטית, אך בפרק
יהיה נקי יותר לומר שהמספרים התקבלו מהקוד המקורי ללא תחליפים.

**נדרש:** כל מכונת לינוקס. **לא נדרש Pi ולא נדרשים מיקרופונים.**

**הרצה:**

```bash
sudo apt update && sudo apt install -y build-essential libfftw3-dev

cd acoustic_detection_v2/acoustic_detection
make clean && make

for SIGMA in 0.001 0.01 0.05 0.10; do
  for RUN in 1 2 3; do
    echo "=== SIGMA=${SIGMA} RUN=${RUN} ==="
    ./test_harness --sweep --noise $SIGMA
    sleep 1     # חובה: test_harness.c:673 מאתחל את מחולל האקראיות לפי time(NULL)
  done
done > docs/chapter11/results/A6_sweep_fftw.txt 2>&1
```

**ההשהיה של שנייה בין הרצות הכרחית.** בלעדיה שלוש ההרצות יקבלו את אותו זרע אקראי ויחזירו
תוצאות זהות, כלומר לא תהיה כאן שום חזרה סטטיסטית.

**מה לתעד:** את הפלט הגולמי. השווה את שורות ה-Summary למספרים בסעיף 1 לעיל.

**צפוי:** התאמה עד הספרה האחרונה.

**אם יש פער:** זה ממצא בפני עצמו, ויש לדווח על שתי הקבוצות.

## 6. קבוצה D — דורש מיקרופונים מחווטים ל-Pi הראשי

### D1 — דיוק זווית אקוסטית בחומרה 🔴 העדיפות הגבוהה ביותר בקבוצה

**מה נמדד:** בדיקת "זיהוי מקורות רעש חריגים" מפרק 10, במדויק.

**למה זה קריטי:** הטענה הקיימת בדבר דיוק של חמש מעלות על מחיאות כף היא **טענה חסרת מקור**.
מסמך התשובות קובע שאין לה לוג, אין פרוטוקול ואין תיעוד, ושהיא מגיעה משורה בודדת במסמך מצב.
אם היא תיכנס לחלק ב' כתוצאה מדודה, לא תוכל להגן עליה.

**פרוטוקול מינימלי, כעשרים דקות עבודה:**

1. סמן על הרצפה במד זווית ובנייר דבק חמישה כיוונים ביחס לציר הקדמי של המערך:
   90 מעלות שמאלה, 45 שמאלה, 0, 45 ימינה, 90 ימינה.
2. מרחק שלושה מטרים מהמערך בכל כיוון.
3. הרץ:

```bash
cd ~/SnipeIt/acoustic_detection
sudo ./snipeit_acoustic | tee docs/chapter11/results/D1_clap_test.log
```

4. מחא כפיים חמש פעמים בכל אחד מחמשת הכיוונים, במרווח של שתי שניות לפחות בין מחיאות
   (זמן העצירה הוא חצי שנייה). סה"כ עשרים וחמישה אירועים.
5. תעד לכל אירוע: זווית האמת, הזווית שהוחזרה, הסטייה, ערך הביטחון, ודגל התקפות.

**אם התכנון הוא שתים עשרה זוויות בצעדים של חמש עשרה מעלות כפי שכתוב בפרק 10, עשה זאת.**
חמש הזוויות לעיל הן המינימום שעדיין מייצר תוצאה בת-הגנה.

**מה לתעד בנוסף:** צילום של הסידור הפיזי, הכולל את המערך, את סימוני הרצפה ואת מד הזווית.
זה ממלא גם את מציין המיקום של תמונת החומרה.

**צפוי:** סטייה של עד חמש מעלות. **ציין במפורש אם זה ממוצע או מקרה גרוע ביותר.**
